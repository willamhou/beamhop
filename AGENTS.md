# Editing this branch

This is the `gh-pages` branch for Beamhop product essays. The application lives on `main`. Keep the essays as static pages, with no external runtime dependencies. The interaction is simulated; it does not send data to agents.

## 去 AI 味：保留意思，再清理表达

本分支采用 shuorenhua（说人话）技能的编辑方法。编辑的是表达，不是判断文章是否由 AI 写成；不要给“AI 含量”打分，也不要按禁词表机械替换。

1. 先读完整段落，确认读者、语境和范围。默认保留长文的句段结构，只改有明确收益的地方。用户要求重组时，才删并、重排有效内容。
2. 列出需要保护的内容：事实、作者判断、谁做什么、条件、否定、可能性、范围、比较、完成状态、数字和下一步。文中说“需要接收端支持”，改稿仍须保留这个前提；“已接收”不能变成“已完成”。
3. 区分正文、引文、界面标签和代码。作为依据的原话、被讨论的措辞、术语、路径、命令、接口名按原文保留。普通去 AI 味不授权修改代码、注释或程序行为。翻译功能另行处理界面字符串，保持标识符、示例地址和行为一致。
4. 在原句上删除无内容的招呼、只提示行文顺序的预告和口头填充；简化名词化、累赘功能词和生硬语序。删重复之前，必须在保留部分找到同一内容的完整表达。有关联或能推断出来，都不算完整重复。
5. 不为换词而换词。不把作者的立场、犹豫、有意重复和具体评价当作套话删除。仅说“去 AI 味”不等于授权删除口号或降低判断强度；只有用户明确要求写平实、去营销或夸张语气时，才额外降调。
6. 不编来源、研究、指标、产品功能和操作步骤。来源不清的归属不能直接删掉，留下仿佛已证实的裸结论。拿不准是否等义，就撤销那处修改。
7. 逐句看实际差异及其上下文。核对删改的实词、限定、关系；原稿独有的内容若不再表达，放回原位。大声读一遍改稿，检查指代、语序与段落衔接。正常的句子可以原样留下。

例如，“完成了对配置的检查”可改为“检查了配置”，但不能因此补出检查结论。“接收端已确认，不代表 agent 已理解、执行或完成工作”则应完整保留其区分。

## English editing

Translate the edited Chinese text in full, including conditions, uncertainty, ownership, and product limitations. Use natural English sentence order without adding claims or deleting the author’s judgment. Keep examples marked as fictional. Translated quotations are translations of the supplied examples, not new interview evidence.

Read each English paragraph against its Chinese source, then read it on its own. Remove empty framing and awkward nominalizations where meaning stays intact. Do not vary terminology merely to avoid repetition. Use **destination** for 去处, **session** for 会话, **clip** for an extracted passage, and **shelf** for the temporary corner panel. **Receipt confirmed** means the receiving side acknowledged the handoff; it does not mean the agent completed the task.

## Product and interaction constraints

- Keep the main action in the source app: select, confirm the destination, send, continue reading.
- In essay 02, the shelf stays at the bottom right. Capturing a clip must not open a work window, expand the shelf, move the page, or focus an input. Preserve selections and notes when the shelf is collapsed.
- Keep source text and provenance. A destination suggestion must not silently replace a confirmed choice. Keep receipt status distinct from execution status.
- Do not replace the article with a dashboard or add a separate workspace to explain nonlinear work.

## Sources and publishing

The homepage is `index.html`. Chinese essays are `handoff.html`, `work-in-hand.html`, and `quiet-panel.html`. Discussion source: `product-notes.md`. The discussion HTML is generated by `python scripts/render-notes.py`, using the first essay's styles from `handoff.html`.

English pages are generated from Chinese pages and reviewed translation catalogs by `python scripts/build-english.py`. Edit the catalogs rather than generated English HTML. The English discussion source is `product-notes.en.md`; the notes renderer builds both languages. Use `python scripts/build-site.py` to run the notes renderer, English builder, and shared navigation in order. `scripts/site_nav.py` owns headers and essay links. Keep its output static and language-specific. Old homepage anchors are forwarded by the allowlist in `legacy-links.js`; `#essays` stays on the homepage.

Essay 03 uses `quiet-panel.css` and `quiet-panel.js`. Its data and timing are simulated. Basic actions never wait for recommendations. Late results must not change a confirmed destination, input, focus, or button position; dismissing invalidates pending results. The proposed first version uses local retrieval and ranking without generative or embedding model dependencies. Do not describe the demo as an implemented recommendation engine or benchmark. The revised demo stores independent material batches and explicit app/session routes. Keep text, file and image identity; unsupported attachments must block handoff rather than disappear. Background receipt, prepared draft and clipboard copy are separate outcomes. Preserve all failed snapshots and make history reachable; retry uses the original route and resolves that record. Restoring a batch must preserve any current material, even without an edited instruction. Receiver capability assignments are fictional. User-selected files stay in browser memory and are never uploaded.

Maintain `README.md` and `README.en.md` together. Page headers must link to the matching article in the other language, and series links must stay in the reader’s chosen language. Translate titles, descriptions, accessibility labels, placeholders, dynamic messages, sample data, and recovery states as well as prose. Do not translate user-entered notes, IDs, selectors, source URLs, or session addresses.

Before publishing, check:

- Text edits preserve each original claim, condition, quotation, and limitation.
- Both language versions contain the full article and the same interactions. Language links and relative asset links resolve.
- Direct send, destination choice, temporary storage, partial batch send, note retention, failure recovery, and receipts work in both languages. User input remains literal text, including punctuation and markup characters.
- The second essay preserves scroll position and paragraph positions during sending and capture. Check the corner shelf and popover at desktop and narrow widths, in light and dark appearance. English labels must not overflow.
- Run `git diff --check`, inspect the staged files, and follow the user’s current publishing authorization. Push without force, then compare local HEAD with the remote branch. Do not claim GitHub Pages is live merely because the branch was pushed.
